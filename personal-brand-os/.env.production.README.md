`.env.production` is committed deliberately: it contains only the two
NEXT_PUBLIC_* Supabase values (project URL + anon key), which are designed
to be client-exposed — they ship in the browser bundle of every deployment
regardless, and all access through them is gated by RLS as the signed-in
user. Committing them here is what lets Vercel build without separate
env-var configuration. No service-role key exists anywhere in this project.
